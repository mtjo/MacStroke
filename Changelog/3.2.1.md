## MacStroke 3.2.1

**新增 / Added**

- The wheel is a gesture now: hold the trigger button (the one recorded on the General page, right button by default) and scroll. Scroll-up and scroll-down are configured separately, so the pair issue #75 asked for — previous tab one way, next tab the other — is exactly what you get.

  按住起手键 + 滚轮现在是手势了。起手键就是「常规」页里录的那一颗（默认右键），上滚和下滚各配一档、互不顶替 —— issue #75 要的「快速切前后标签页」照这个配法直接成立。

- Per direction: 无 / 上一个标签页 / 下一个标签页 / 音量 +1 档 / 音量 −1 档 / 自定义快捷键（再给一个录入框）。开关一开，上滚默认是「上一个标签页」、下滚默认是「下一个标签页」，想换再换；那颗总开关本身默认关。

  每一档可选：无、上一个标签页、下一个标签页、音量 +1 档、音量 −1 档、自定义快捷键（选这档时才用得上旁边的录入框）。总开关默认关 = 原版行为；开了以后上滚默认「上一个标签页」、下滚默认「下一个标签页」，正好是 issue 里那件最想要的事。

- These settings live on the page formerly called 右键菜单, now 右键增强 ("Right-click extras") — it held the list of apps that show MacStroke's menu entry, and that list is still there untouched; the new scroll section sits under it.

  这一组放在原先叫「右键菜单」的那一页，现在叫「右键增强」—— 那页本来管的是「哪些软件的右键菜单里要出现 MacStroke」，那份列表原样还在，滚轮这组排在它下面。名字得跟着改：一页两件事，还叫「菜单」就说不清了。

- One notch is one action, and that notch is swallowed: the page underneath does not move at the same time. A direction set to 无 swallows nothing at all. And once a scroll has fired, releasing the button does not pop the right-click menu and does not match whatever half-arc your hand drew on the way — one gesture, one result.

  一格算一次动作，并且那一格会被吞掉 —— 下面的页面不会跟着滚。配成「无」的那个方向一个事件都不拦，跟这一版之前一模一样。触发过滚轮之后松手，既不弹右键菜单，也不再拿你顺手画的那半条弧线去匹配规则：一次手势只留一个结果。这正是「滚一下只是想切页，别顺手给我弹菜单」要的口径（和 issue #73 提的「不匹配时别弹菜单」同一个方向，那颗开关照旧独立生效）。

- Volume goes straight to the system: one notch is +5% / −5% of the default output device, clamped at both ends, per audio channel. (The multimedia-key route that apps like this usually take cannot be injected from a normal process — verified on this machine — so it reads and writes the CoreAudio scalar instead.) Plugging in headphones or an external display moves it along with the system's default device.

  音量那两档直接读写默认输出设备的标量音量：一格 ±5%，两头钳住，逐声道落。以前那类做法是投一发「音量+」多媒体键，本机实测命令行进程投不动（要走系统私有那条线），所以这版走 CoreAudio。插耳机、接外接屏之后音量跟的是系统默认设备，本功能不另外记设备。

- Chinese text now actually slants when you press italic (issue #73). PingFang SC ships no italic face, so asking the font engine for one just gets the upright run back; we now synthesise the slant for exactly those runs, while Latin keeps its own true italic. Mixed wording is split per resolved face, so in 「重要 note」 the Chinese gets the synthetic slant and the Latin its real italic — at the same angle, one ~11° shear, so the two don't look like different fonts.

  中文斜体修好了（issue #73）：苹方根本没有斜体那一款字面，字体引擎被要到「斜体」时只能把正体原样还给你，所以按了跟没按一样。现在这类没有斜体字面的字体由我们自己补一个倾斜量（合成斜体），拉丁字母仍用它自己的真斜体；中英混排按解析出的字面逐段切开，所以「重要 note」这一句里中文走补出来的那一档斜、英文用系统字体那款真斜体，两者倾角同一档，看上去是一路的字。

- The 关于 page's 已跳过的版本 row now tells the truth. It used to print the label and a colon and nothing else — skipped or not, it looked empty — and pressing 恢复提醒 changed nothing on screen, because the only reply was a system notification that 勿扰 can swallow entirely. It now lists the actual version numbers (all three of Sparkle's skip slots, including the numeric ones older installs left behind), greys the button when there is genuinely nothing to restore, and after clearing leaves one line under the row saying which versions were un-skipped and whether a check was re-armed. The row itself does not move.

  关于页那行「已跳过的版本」修好了：以前只有标题和一个冒号，跳没跳过都一片空白；按「恢复提醒」页面上也什么都不变 —— 唯一的回执是一条系统通知，而勿扰能把它整个压掉，于是看起来就是「点了没反应」。现在冒号后面真的写出版本号（Sparkle 记跳过的那三格都读，老装机留下的数字型记录也收），没得恢复时按钮灰着说破，清完在行下方留一句「已清除哪几版 / 有没有顺手补一次检查」，那一行本身不跟着位移。急着要更新包的话，上面那颗「立即检查更新」一直都不看跳过记录。

**注意 / Notes**

- Off by default, and off means off at the root: the scroll listener is a second event tap, kept separate from gesture capture, created disabled and only armed while the trigger button is held. A disabled tap delivers nothing — no wheel event enters the callback, so the cost is zero — and arming ends the moment the gesture ends, including when a gesture is cancelled (pointer teleported off-screen, Synergy-style). Gesture recognition and latency therefore don't change for anyone who doesn't turn it on; the Accessibility permission already asked for at launch is the only one needed.

  整条功能默认关，而关掉是关到根上：滚轮走的是**另开的一条事件监听**，跟手势捕获那条分开，建出来就是禁用状态，只在起手键按着的那一小段里上膛。关着的 tap 一个事件都不会进回调，代价为零；手势一结束（含被取消 —— 指针瞬移那种）当场收膛。开关不开时识别耗时与延迟跟这一版之前完全一致。要的权限还是启动时已经要求过的「辅助功能」，不多要。

- Throttling and high-resolution wheels: a notch counts once it reaches one full line and no sooner than 0.09 s after the last fire, so a free-spinning wheel or trackpad inertia doesn't fire twenty tabs in a row. Trackpad two-finger scroll is the same event class, so holding the trigger button while you scroll on a trackpad does trigger it. Scrolling that arrives while a rule gesture is being drawn is left completely alone — the recording panel won't switch tabs under you.

  节流与高分辨率滚轮：累计够一格、并且离上一次触发过了 0.09 秒才算一次，所以鼠标自由轮和触控板的惯性不会一口气切二十个标签页。触控板双指滚动也是同一类事件，按住起手键时它照样算 —— 不想要就把总开关关掉。在「绘制手势」那个录制面板里滚轮掺进来时一律不触发，只收轨迹，不会一边画一边把标签页切走。

- 按住让位修饰键（「常规」页那个开关，issue #59）时滚轮也一并让：⌘ + 滚在多数浏览器里本来就是横向滚动，这里不抢。两个方向都配成「无」（或选了自定义快捷键却没录键）时页面会出现一行橙色提醒 —— 功能开着但什么都不会发生，说破比让你以为它坏了强。快捷键录入框旁边那颗叉可以清空，清空等于那一方向什么都不做（不是录成某个键）。

  按住「让位修饰键」时（⌘ 那一组，见「常规」页）滚轮一个都不接，交回前台应用。两个方向都没配动作时页面上会出现橙色那句提醒；录入框右侧那颗叉是清空，清空 = 这一方向什么都不做，而不是变成一个真实的键。

- "Previous / next tab" sends the two keys the system agrees on: ⌘⇧[ and ⌘⇧] (Safari, Chrome, Terminal and most editors bind that pair). An app that insists on something else gets the 自定义快捷键 direction — click into the recorder and press the app's own combination once. An empty recorder means that direction does nothing, so it can never fire a key nobody asked for.

  「上一个 / 下一个标签页」这两档投的是 ⌘⇧[ 和 ⌘⇧]，是系统里最通用的一对（Safari、Chrome、Terminal、多数编辑器都这么绑）。某个软件偏偏用别的键，就把那一方向换成「自定义快捷键」，点进录入框按一次那个软件自己的组合键即可 —— 框里空着等同于选了「无」，不会瞎发一个键。
