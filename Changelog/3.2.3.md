## MacStroke 3.2.3

**修复 / Fixed**

- A black list (or white list) you saved no longer disappears when MacStroke restarts (issue #76). The page itself was always writing correctly — the wiping came from the launch-time migration that turns MacStroke 2.x's single old `blockFilter` string into the per-line list. That legacy key had been given a registered default of `""`; a registered default is visible to exactly the read the migration performs, and `removeObject` can only delete a value that was really written to disk. So "an old list is waiting to be migrated" held true on every launch, and every launch overwrote your list with that empty one and pushed the mode back to black list. It has been this way since 3.0.0, i.e. every version so far — and the same line of code was harmless in 2.x, which never registered the key.

  重启后黑名单变空这件事修好了（issue #76）。偏好页那条写库的路一直是对的，清掉它的是**启动时那一次 2.x 旧名单迁移**：旧键 `blockFilter` 被多注册了一份 `""` 当默认值，而注册表里的值恰好对迁移用的那一句读取可见，`removeObject` 又只删得掉真正写进磁盘的那一份 —— 于是「有旧名单要迁」每次启动都成立，每次启动都拿那份空的把名单重写一遍、顺手把模式按回黑名单。这条从 3.0.0 起就在（也就是此前每一版都这样）；原版从不注册这个键，所以同一行代码在原版身上是无害的。

- The mode is no longer changed behind your back either: that same migration also forced black-list mode, so anyone using white-list mode lost the mode together with the list. Both the lists and the mode are now touched only when the old key carries an actually-written, non-empty list.

  模式也不再被背着改：同一次迁移还会把模式按成黑名单，所以用白名单的人连模式带名单一起丢。现在判据是「旧键里真写过、而且那份不是空的」，两条都成立才动名单和模式。

**注意 / Notes**

- Entries already wiped cannot be recovered — the old key was deleted by the very first wrong migration, so there is nothing left to read back. Re-add the ones you need once; from this version they survive restarts, upgrades and 恢复默认设置. If you genuinely upgraded from MacStroke 2.x and that old key still holds a list, it migrates exactly as before, exactly once: the first launch of this version moves it into the black list (2.x only had a black list, so the mode lands on black list), then deletes the old key and later launches leave it alone.

  已经被清掉的那几项找不回来 —— 旧键在第一次误迁时就被删了，没有地方可以回读。请重新加一次，之后重启、升级、点「恢复默认设置」都不会再丢。真的从 2.x 升级上来、旧键里还留着名单的人不受影响：这一版第一次启动照样把它迁进黑名单（2.x 只有黑名单，所以模式落在黑名单）并删掉旧键，之后每次启动都不再碰它。

- When the migration does move something, it now says so: one `[BlockFilterMigration]` line in the log carrying how many entries came over. A launch with nothing to migrate writes nothing, for the same reason the "feature off" lines stay silent — useful lines shouldn't get buried.

  迁移真动手时会在日志里留一行 `[BlockFilterMigration]`，写明迁进来几条；没东西可迁就一个字不写，道理和「功能没开」那档不写行一样 —— 别把有用的行埋掉。

- Nothing else moved: no new setting, no new permission, no preference key added or dropped (the old key simply no longer carries a registered default), and the filter page looks exactly as it did.

  其余一律没动：没加设置项、没要新权限、没有新增或去掉任何偏好键（只是不再给那个旧键注册一份默认值），过滤页面上也和之前一模一样。
