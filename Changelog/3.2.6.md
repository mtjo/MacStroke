## MacStroke 3.2.6

**修复 / Fix**

- The clipboard-history shortcut no longer stays dead after macOS disables its event tap. The system switches a tap off on its own — after an input timeout, or when a secure-input field or Accessibility tool takes over — and until now nothing turned it back on unless another matching keypress happened to arrive, so the shortcut could stop responding for a whole session. A watchdog now checks every 2 seconds: if the tap was merely disabled it is re-armed, and if the underlying port is gone the tap is rebuilt from scratch. Nothing changes when the tap is healthy — still no key is consumed, and the default ⌥⌘V is untouched.
- One more thing worth saying plainly: the report that led here was not a code path quietly rewriting the shortcut. The stored binding had become ⌃⌘A (most likely committed once through the recorder box on the Clipboard page, which stores whatever is pressed). The default remains ⌥⌘V, and this release neither changes nor resets your binding — if your shortcut row shows something other than ⌥⌘V, press the recorder and set it back once; from this version on, a disabled tap no longer adds a second reason for silence.

  粘贴板历史的全局快捷键不会再因为事件 tap 被系统停用而一直失灵。系统会自行停掉 tap —— 输入超时、或安全输入框/辅助功能工具接管时 —— 而在此之前没人把它重开，只有恰好又来一记匹配的按键才会顺手恢复，所以一整场都可能按了没反应。现在每 2 秒巡检一次：只是被停用就重新上膛，底层端口没了就整只重建。tap 健康时行为不变 —— 照样不吞任何按键，默认的 ⌥⌘V 也没有任何改动。

  另说清楚一件事：这次的问题不是代码路径在悄悄改键。存储里的绑定值变成了 ⌃⌘A（最可能是某次在粘贴板页的录制框里按了一下，录制框按什么存什么）。默认仍是 ⌥⌘V，这一版既不改也不重置你的绑定 —— 如果你看到的快捷键行不是 ⌥⌘V，点一下录制框重新设一次即可；从这一版起，tap 被停用不会再额外多出一个失灵的理由。
